## 2. 设备怎么接

1. 腾讯云安全组放行 **TCP 8010**（当前只在本机验证过，公网可达性未确认）。
2. 设备配置网页 `server_url` 填 **`http://<SERVER_IP>:8010`**（不要带 `/upload`）。
3. 点设备网页「服务器检查」→ 应显示 `status: ok`。
4. 固件端无需任何改动：协议与 `docs/backend-api.md` 完全一致。

> 上传接口实测响应 **27~60ms**，远低于固件 20s 超时（转写是异步的）。
> 但 15 分钟 WAV ≈ 28.8MB，如果家里宽带上行很慢，建议把设备 `segment_seconds` 调到 300（≈9.6MB）。

## 7. 常见坑（调试手册）

| 现象 | 原因 / 处理 |
|---|---|
| 设备 `ESP_ERR_HTTP_CONNECT` | 安全组没放行 8010，或 `server_url` 带了 `/upload` 路径 |
| `docker pull` 卡死 | 国内直连 Docker Hub 不通；用 `docker.m.daocloud.io/library/` 前缀 |
| ASR 容器 `loaded:false` 很久 | 首次要下 1GB 模型（3~8 分钟）；`docker logs recbean-asr` 看进度；挂了会自己重启 |
| **ASR 容器被 OOM/Killed** | 曾给它设 2.2GB 硬上限导致加载卡死；**现在不设上限**（模型常驻 2.8GB）。别再加 `mem_limit` 到 asr 上 |
| 转写失败 `ConnectError: name resolution` | backend 启动时 asr 还没就绪，队列会自动重试，无需干预 |
| LLM `HTTP 404` | Base URL 补 `/v1` 的问题：末段已是 `v3` 这类版本号时不再补 |
| LLM `401` | Key 填成了模型 ID（曾发生过）；用控制台的真实 `sk-` Key |
| LLM 回复为空 | 推理模型正文可能在 `reasoning_content`，代码已兜底 |
| 推送没收到 | 逐渠道点「发送测试」；钉钉/飞书开了加签必须填 Secret |
| 部署后配置没了 | 配置在 `data/config.json`，只要 `data/` 挂载在就还在 |

## 7.1 自动任务的跳过规则（重要）

**没有录音就什么都不做**：无上传 / 无可用转写 → 不调 LLM、不生成空日记、不推送；
日记已存在 → 只补推送不重新生成。三处入口（定时、手动 API、转写队列）都已统一加判断，
细节见 `docs/skip-rules.md`。排查时看后端日志里的 `[sched] ... 跳过总结与推送`。
