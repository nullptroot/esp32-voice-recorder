## 4. 开发过程中修复的问题

1. **`sentence_timestamp=True` 导致 `KeyError: 'timestamp'`** —— paraformer-common 不输出逐字时间戳，去掉该参数、只用 VAD 分段结果。
2. **推理模型返回 `reasoning_content`** —— 腾讯 TokenHub 的 deepseek-v4.1 在小 `max_tokens` 时 `content` 可能为空、正文在 `reasoning_content`，已做兜底提取。
3. **LLM Base URL 拼接** —— `https://tokenhub.tencentmaas.com/plan/v3` 已带版本段，不能无脑补 `/v1`；改为识别末段 `vN` 自动判断。
4. **列表/日记时间线乱序** —— ISO8601 字符串带时区不能直接比较排序，改用 `datetime()` 归一化。

## 4.1 自动任务"不做无意义操作"（23:24 补充）

用户要求：当天没有录音文件就不该做多余操作。已收紧三处入口（详见 `docs/skip-rules.md`）：

- 无任何上传 / 无可用转写文本 → **不调用大模型、不生成空日记、不推送**；
- 当日日记已存在 → 定时任务只补推送，不重复烧 token；
- 手动接口传无数据日期 → 直接返回明确错误，不落脏数据；
- 转写 worker 无待处理时不下发任何 ASR 请求；
- 后台「上次总结」会显示 `无录音，已跳过`，能区分"真跑"和"跳过"。

实测：`/api/summarize` 空日期返回 `已跳过（不调用大模型）`；`/api/push` 空日期返回 `还没有总结，不推送`；
定时任务空日期日志 `无录音/转写，跳过总结与推送`；有数据日期正常。

## 5. 已知限制

| 限制 | 说明 / 建议 |
|---|---|
| **无 GPU，2 核 CPU** | 15 分钟录音转写约 5~15 分钟（RTF 0.3~1.0）；现在是**异步队列 + 自动重试**，不阻塞上传。若要求更快，需换 GPU 或减小记录粒度 |
| **ASR 常驻约 2.8GB 内存** | 与 mem0 三件套共存约 3.1GB / 3.6GB，余量小。极端情况会吃 swap。若要更省内存可换 `SenseVoiceSmall`（约 1.5GB） |
| **服务器无公网可达性（待确认）** | 服务监听 `0.0.0.0:8010`，但腾讯云**安全组需放行 TCP 8010** 才能让设备直连 |
| **设备端 20s 超时 vs 大文件上传** | 15 分钟 WAV ≈ 28.8MB，手机/家里宽带上行 <1.4MB/s 时可能超时；建议设备端 `segment_seconds` 调小（如 300s≈9.6MB） |
| **推送渠道只实测了 Bark / ntfy** | 其余 5 个渠道代码按官方协议实现（含钉钉/飞书 HMAC 加签），需要你填真实 key 后在 Web 上点「发送测试」确认 |

## 6. 遗留 / 下一步建议

1. **安全组**：放行 8010，或在宿主机上做 Nginx 反代 + HTTPS + IP 白名单。
2. **改默认密码**：`admin / recbean` 必须在「系统」页改掉。
3. **开其它推送渠道**：填 key 后逐个「发送测试」。
4. **设备端联调**：设备网页 `server_url` 填 `http://<SERVER_IP>:8010`（不带路径），点「服务器检查」应返回 `status: ok`。
5. **可选增强**：SenseVoice 小模型替换（省内存）、日记全文检索、OTA 配置下发、多设备别名。
