# 录音豆 RecBean · 项目介绍

> 这份文档回答三个问题：**为什么要做**、**它到底是什么**、**现在做到哪了**。
> 面向：视频脚本作者 / AI 剪辑 / 潜在开源用户。
> 所有事实均可追溯到仓库内 `README.md`、`docs/handover-2026-10-31.md`、`docs/progress-2026-10-31.md`。

## 1. 一句话

**市面上卖 600~700 元的「录音豆」，我用约 65 元的模块、从零写固件，自己做了一个：声音来了才录，录完存本地，回家自动上传，而且完全开源。**

---

## 2. 为什么做这个

### 2.1 市面上的问题

| 问题 | 具体表现 |
|---|---|
| **贵** | 主流 AI 录音豆 / 录音卡片普遍 600~700 元，硬件成本远低于售价 |
| **订阅制** | 转写、摘要、云端存储按年收费，不续费就变砖 |
| **数据不在自己手里** | 录音上传到厂商云，隐私边界不透明 |
| **功能被锁死** | 只能用官方 App，不能改采样率、不能改触发逻辑、不能接自建服务 |

### 2.2 我的判断

这类设备的技术栈并不神秘：**MCU + 数字麦克风 + 存储 + 上传**。
真正难的是工程细节——低功耗唤醒、误触发、断电时间、SD 卡供电、长稳。
既然这些都能自己啃下来，那就没必要为「品牌 + 云服务」付 10 倍溢价。

### 2.3 所以这个项目的目标

> 做一个**百元以内、数据完全自主、功能可自定义**的全天候录音终端，
> 并把从零到跑通的全部过程（代码、踩坑、验证数据）开源出来。

「从零」是真的从零：**网购模块 → 自己焊排针 → 杜邦线接线 → 写固件 → 搭后端**。
没有任何现成的录音方案可以抄，连引脚冲突都是自己一个个试出来的。

## 3. 它是什么 / 不是什么

### 3.1 是什么

一台**事件驱动**的录音终端：

```
深睡（WiFi / httpd 全关）
   │  LM393 检测到声音超过阈值 → 硬件中断唤醒
   ▼
预录 1.5s 环形缓冲
   │  轻量 VAD 二次确认（能量 + 过零率，连续 3 帧）
   ├─ 不是人声 → 冷却 20s → 回深睡（不产生文件）
   └─ 是人声 → 写 WAV 到 SD（16kHz/16bit/单声道，15 分钟分段）
                 │  静音 5s 自动停录
                 ▼
              上传（multipart + 指数退避 + 断点续传标记）
                 │  成功后删本地 / 失败保留重试
                 ▼
              回深睡
```

### 3.2 不是什么

- 不是**实时监听/直播**设备：录音时主动关 WiFi，减少射频干扰。
- 不是**会议记录仪**：它是「全天候、无感、按事件触发」的耳朵，不是长录。
- 不是**云服务**：设备端不做转写，后端可以是你自己的树莓派/NAS。

## 4. 核心能力（已验证）

| 能力 | 说明 | 状态 |
|---|---|---|
| 声音唤醒 | LM393 DO 接 GPIO15，EXT1 低电平唤醒 | ✅ 实测 |
| VAD 二次确认 | 自适应噪声底 + 能量门限 + 过零率，3 帧确认 | ✅ 单测 + 实测 |
| 误触发冷却 | VAD 否决后冷却 20s，不产生垃圾文件 | ✅ |
| 预录 | 1.5s 环形缓冲，唤醒瞬间的声音不丢 | ✅ |
| WAV 写卡 | 16kHz/16bit/mono，44 字节标准头，关闭时回填 | ✅ ffprobe 验证 |
| 分段 | 默认 15 分钟一段，网页可改 | ✅ |
| 静音停录 | 5s 无人声自动收尾 | ✅ |
| 上传 | multipart + 指数退避 2/4/8/16/32s + `.up` 标记 + 去重 | ✅ 累计 121 条，末批 17 个积压文件一次传完 0 失败 |
| 断网不丢数据 | 上传成功前不删文件，开机补传 | ✅ |
| 断电时间恢复 | NVS 存上次时间，开机恢复近似时间，联网 NTP 校正 | ✅ |
| 网页配置 | 20+ 参数热改、设备日志、文件列表、立即深睡 | ✅ |
| 深睡唤醒 | EXT1：声音（GPIO15）/ 配置键（GPIO14），唤醒后 300s 配置窗口 | ✅ 端到端 22.3s |
| 手动按键 | GPIO41 短按启停 / 长按补传 | ✅ 杜邦线实测 |
| 双核绑核 | 录音 worker 固定 core 1，httpd/LED 在 core 0 | ✅ |

## 5. 硬件与成本

测试阶段全部用**模块 + 杜邦线**，没有画板、没有外壳、没有电池。

| 配件 | 型号 | 价格 |
|---|---|---:|
| 主控开发板 | 立创 ESP32S3R8N8（8MB Flash + 8MB PSRAM） | ¥35.9 |
| 数字麦克风 | INMP441（I2S） | ¥4.0 |
| 声音检测 | LM393 比较器模块 + 驻极体 | ¥2.0 |
| 存储 | MicroSD 模块 + 32GB TF 卡 | ¥8.0 |
| 电源 | TP4056 充电模块（带保护） | ¥0.5 |
| 电池 | 3.7V 1000mAh 锂电（估算） | ¥10.0 |
| 杂项 | 杜邦线、按键、电阻、LED | ¥5.0 |
| **合计** | 不含外壳 / PCB 打样 | **≈ ¥65.4** |

> 口径说明：65 元是**物料估算**，不含外壳、PCB 打样、快递。
> 视频里统一说「65 块」「百元以内」，不要说「精确 65 元」。
> 市面 600~700 元这个区间来自用户提供的调研，发布前建议再复核一次，**不要点名具体品牌**。

## 7. 关键技术数字（视频里可用的「可信细节」）

- 固件：ESP-IDF **v5.5.6**，产物 `recbean.bin` 约 **1.13MB**
- 音频：**16kHz / 16bit / 单声道**，约 **112.5MB/小时**
- 唤醒 → 录音 → 上传全链路：实测 **22.3 秒**
- 连续录音稳定性：**10/10** 次成功
- 上传记录：后端累计 **121 条**，0 失败
- 深睡唤醒：EXT1，`mask=0x4000`（GPIO14 配置键）
- 供电：SD 模块 **必须 5V**（3V3 压差不足会随机 CRC）
