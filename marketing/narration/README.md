# 旁白配音（TTS 输入）

> 这里放的是**已经处理好读法**的口播文本，直接喂给你的 S2 Pro 就行。
> 一个场景一个文件，方便你分段生成、单独重录、精确对轴。

---

## 1. 文件怎么用

```
narration/
├── vo-01.txt ~ vo-12.txt   每段一条，复制进 TTS
├── vo-full.txt             整段（想一次性生成时用）
└── segments.json           每段的目标时长 / 字数 / 语速（给校验脚本读）
```

**推荐流程**：逐段生成 `vo-01.wav` ~ `vo-12.wav`，命名和 txt 一一对应，放进 Remotion 的 `public/audio/`。
一次性生成 `vo-full.wav` 也可以，但后面改一句就要整段重录，不推荐。

## 3. 为什么文本里数字是中文

TTS 对符号和缩写经常读错，所以这些**已经在 txt 里处理好了**，你不要改回去：

| 原写法 | 文本里的写法 | 原因 |
|---|---|---|
| 65 | 六十五 | 防止读成「六五」 |
| ¥699 | 六七百 | 符号 `¥` 会被漏读或读成「元」 |
| 5V | 五伏 | `5V` 常被读成「五 V」 |
| 350℃ | 三百五十度 | `℃` 符号不可靠 |
| 35.9 | 三十五块九 | 小数点+元，读起来别扭 |
| ESP32-S3 | （口播里没出现） | 这串字符 TTS 必翻车，改用「主控」 |
| I2S | I 二 S | 字母+数字混读容易糊 |
| SPI | S P I | 直接给字母，逐字读 |
| VAD | V A D | 同上 |
| RTC | R T C | 同上 |
| GPIO15 | 十五号脚 | 引脚号更口语，观众也懂 |
| SD | SD | 这个词 TTS 基本都读对，保留 |
| star | 星 | 避免读成「斯达」 |

如果 S2 Pro 把某个词读错，**只改那个词**，别重写整句。

## 4. S2 Pro 参数建议

| 项 | 建议 | 说明 |
|---|---|---|
| 音色 | 成熟男声 / 中性偏冷 | 不要甜妹音，跟「硬核 DIY」不搭 |
| 语速 | 1.00–1.06 | 先 1.0 生成，快了再降，不要一开始就 1.2 |
| 情感 | 中性偏讲述 / narration | 不要「激情带货」 |
| 采样率 | 48kHz | 和视频音频轨一致，省一次重采样 |
| 格式 | WAV | 无损，方便统一响度 |
| 停顿 | 靠标点控制 | 句号 ≈ 0.3s，逗号 ≈ 0.15s；不够就手动加「，」 |

**统一响度**：所有段生成后统一到 **-16 LUFS**（抖音/小红书的标准），
不然会出现「钩子很响、后面很轻」的情况。用 Audacity「响度归一化」或 ffmpeg `loudnorm` 都行。

**降噪**：TTS 本身很干净，除非有底噪，否则**不要**再降噪，容易把尾音削掉。

## 5. 生成后校验时长

```bash
python3 marketing/tools/check_voice_durations.py
```

它会读 `narration/vo-*.wav`，对比目标时长，告诉你：

- 哪段超时 / 太短
- 建议的 `playbackRate`（Remotion 里直接填）
- 哪段还没生成

判定标准：**±15% 以内**可以直接用；超出就重生成或调语速，别硬拉时间轴。

## 6. 常见问题

| 现象 | 处理 |
|---|---|
| 「六十五」被读成「六十五块」多了个块 | 正常，中文语境会补量词，不用管 |
| 「一针一针」读得像「一针一针焊」连读 | 在中间加逗号：`再一针，一针焊` |
| 「I 二 S」读成「艾二艾斯」 | 可以接受；实在别扭就改成「串行音频总线」 |
| 某段整体偏慢，画面等它 | 优先把该 Scene 的 `durationInFrames` 加 10~20 帧 |
| 某段太快听不清 | 降语速重生成，别用 0.9 倍速硬拖（会闷） |
| 结尾「点个星」太突兀 | 在「仓库在简介」后加句号，让它停一下 |
