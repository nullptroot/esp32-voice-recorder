# 设备配置网页 · 使用说明与参数含义

> 地址：`http://<设备IP>/`（默认 `192.168.5.32`，DHCP 可能变化，见 §1）
> 来源：`firmware/main/index.html`（编译进固件），接口在 `firmware/main/web_config.c`
> 适用固件：recbean 1.0（ESP-IDF v5.5.6）

---

## 1. 打开网页

设备连上 WiFi 后，用浏览器访问它的 IP。获取 IP 的三种方式：

| 方式 | 操作 |
|---|---|
| 串口日志（最可靠） | `idf.py -p /dev/ttyUSB0 monitor`，找 `wifi: 获得 IP: 192.168.5.32` |
| 设备状态接口 | 已知旧 IP 时：`curl -s http://<IP>/api/status`（`ip` 字段） |
| 路由器后台 | 找 MAC `44:1b:f6:81:c9:98` 的设备 |

前提：`bench_mode = 开`（默认）。关掉 bench 后设备会进深睡，网页不可访问；
非 bench 也启用深睡时，只在开机那几秒内可访问（如果要长期调试，保持 bench）。

## 2. 页面结构

```
┌ 顶部徽标：状态 / WiFi / IP / 时间可信度 ─────────────────────┐
│ 运行状态卡   录音参数卡   网络卡   上传策略卡   电源/模式卡   │
│ 录音文件表（可下载）                                         │
│ 设备日志（最近 100 条，可滚动）                               │
└──────────────────────────────────────────────────────────────┘
```

页面每 **2 秒** 刷新一次状态、每 **5 秒** 刷新一次日志；文件表与配置不会自动刷新（点按钮）。

---

## 3. 顶部徽标

| 徽标 | 取值 | 含义 |
|---|---|---|
| 状态 | `idle` | 空闲，可触发录音/上传 |
| | `pre_record` | 预录 + VAD 人声确认中（EXT1/自动触发时） |
| | `recording` | 正在录音并写卡 |
| | `uploading` | 正在上传（此状态不要拔电） |
| | `cooldown` | 误触发冷却中（VAD 未确认人声） |
| | `sleeping` | 即将进入 EXT1 深睡（仅非 bench 模式） |
| | `error` | 故障（看「运行状态」卡里的 `last_error`） |
| WiFi | 已连接 / 未连接 | 未连接时设备只能本地录音，网页也打不开 |
| IP | 例 `192.168.5.32` | 当前 DHCP 地址 |
| 时间 | `NTP 已同步` | 时间可信，文件名用 `mic1_YYYY-MM-DD_HH-MM-SS_partN.wav` |
| | `不可信(会话编号)` | NTP 失败，文件名回退 `mic1_session-XXXX_partN.wav`，上传 `time_trusted=false` |

## 4. 运行状态卡

| 项目 | 含义 | 正常参考 |
|---|---|---|
| SD 可用 | 剩余空间（MB，缓存值，未实时 `f_getfree`） | 应接近卡容量 |
| 待上传 | SD 上还没有 `.up` 标记的 WAV 数量 | 上传完成后应为 0 |
| 已上传 | 本次开机以来成功上传的段数 | 随录音增长 |
| 本次录音 | 当前分段已录秒数 | 录音时递增 |
| LM393 DO | GPIO15 实时电平 + 是否判定为「有声音」 | 安静 `LOW · 安静`，拍手 `HIGH · 有声音` |
| 实时电平条 | 最近一帧 RMS（dBFS），-80→0 映射为 0→100% | 安静约 -50，正常说话 -25 左右 |
| 状态消息 | 当前录音/错误/最近上传文件名 | `last_error` 非空时要关注 |

> 电平条是**判断麦克风是否正常工作的最快手段**：说话时应该明显跳动，否则查接线或调增益。

## 5. 录音参数

| 字段 | 含义 | 单位/范围 | 默认 | 调整建议 |
|---|---|---|---|---|
| 采样率 `sample_rate` | 音频采样率 | 8000 / 16000 / 32000 | 16000 | 保持 16000；8000 文件更小但音质差 |
| 增益 `gain_shift` | 16bit 转换时的额外左移位数（0=0dB，1=+6，2=+12，3=+18，4=+24） | 0–4 | 3 | 说话偏小→4；爆音/削顶→2；**改了要重录验证** |
| 分段时长 `segment_seconds` | 每个 WAV 的最大时长 | 5–3600 秒 | 900（15min） | 验收调试用 15–60；正式 900 |
| 最长录音 `max_record_seconds` | 单次录音会话上限 | 5–7200 秒 | 1800 | 一般 ≥ 分段时长；调试设 15–30 |
| 预录窗口 `pre_record_ms` | 触发后先缓存多久再判断（也决定 VAD 确认窗口） | 300–10000 ms | 1500 | 默认即可；调到 2000 可多留住开口前的声音 |
| 静音停录 `silence_stop_ms` | 检测到人声后，静音多久自动停 | 0–60000 ms，0=不自动停 | 5000 | 说话场景 2000–5000；纯手动测试设 0 |
| 误触发冷却 `cooldown_seconds` | VAD 判定非人声后，强制安静多久 | 0–3600 秒 | 20 | 误唤醒多→60–120 |
| VAD 阈值 `vad_threshold_db` | 比噪声底高多少 dB 判为人声 | 2–40 | 8 | 现实测试 6 更灵敏；噪声大→10–12 |
| 启用 VAD `vad_enable` | 预留开关 | on/off | on | ⚠️ 当前固件**始终启用** VAD（EXT1 二次确认必需），此开关暂无效果 |
| 录音时关 WiFi `wifi_off_while_recording` | 录音期间断开 WiFi，减少射频干扰 | on/off | on | bench 调试时**会自动忽略**（否则网页失联）；正式形态保持开 |

### 静音停录的实际行为
- **只有检测到过人声之后**才开始计静音时间，所以手动点「开始录音」后不会在你开口前就停；
- 若一直不说话，录音会持续到 `max_record_seconds`；
- 设为 0 表示只能手动停止（或到最长时长）。

### 分段与文件命名
- 时间可信：`mic1_2026-10-29_01-18-53_part1.wav`（每段用该段开始时刻，`partN` 递增）
- 时间不可信：`mic1_session-0007_part1.wav`
- 每段旁边会生成同名 `.json`（元数据，上传时作为表单字段来源）
- 上传成功后会生成 `.up`（避免重复上传）；`.wav` 本身默认不删

## 6. 网络

| 字段 | 含义 | 说明 |
|---|---|---|
| WiFi 名称 | STA 要连接的 SSID | 点「扫描 WiFi」可列出周围 AP 和信号强度 |
| WiFi 密码 | WPA2 密码 | 明文显示，注意隐私 |
| 后端地址 | 上传目标，形如 `http://192.168.5.36:8000` | 不要带结尾斜杠（代码会处理，但保持规范） |
| 设备 ID | 上传元数据 `device_id` | 默认 `esp32s3-001`；多设备时区分 |

**改完 WiFi 后需要重启**（保存配置不会立即重连）。

## 7. 上传策略

| 字段 | 含义 | 默认 | 说明 |
|---|---|---|---|
| 录完立即上传 `upload_on_record` | 每轮录音结束后自动上传 | on | 关掉则只在开机/按键/手动时上传 |
| 开机扫描补传 `upload_on_boot` | 开机把 SD 上积压的待传文件传完 | on | 断电重启后自动补传 |
| 上传后删除本地 `delete_after_upload` | 服务器返回成功即删本地 WAV | off | 开之前确认服务器可靠 |
| 本地保留（天）`keep_days` | 超过 N 天的文件自动删 | 7 | 0=不按天清理；**仅时间可信时生效** |
| 最大重试次数 `upload_max_retry` | 单文件最多尝试次数 | 5 | 1–20 |
| 退避初值 `upload_backoff_ms` | 首次重试等待，之后翻倍（上限 60s） | 2000 | 200–60000 |
| SD 挂载失败时格式化 `format_sd_if_mount_failed` | 挂载失败自动 FAT32 格式化（**清空卡**） | 开 | 换新卡时最有用；卡里有数据就关掉 |
| SD SPI 时钟 `sd_freq_khz` | SPI 时钟频率 | 代码默认 1000，本机 NVS 为 20000 | 杜邦线长/劣质卡→1000；好卡/短线→20000（上传更快） |

## 8. 电源 / 模式

| 字段 | 含义 | 默认 | 说明 |
|---|---|---|---|
| Bench 模式 `bench_mode` | 常醒 + 网页常驻 + 录音时不关 WiFi | 开 | **调试必开**；关掉才会真正深睡 |
| 启用 EXT1 深睡 `sleep_enable` | 录音/上传结束后进深睡，LM393 拉高水平唤醒 | 关 | 需同时关掉 bench 才生效 |
| LM393 声音时输出低电平 `sound_active_low` | 唤醒极性与「有声音」判定 | 开 | **2026-10-29 实测本模块为低有效**：安静 HIGH、有声音时 10~20ms 低脉冲 |
| 页面底部按钮 | 保存配置 / 重新读取 / 格式化 SD / 重启 | — | 格式化与重启都会二次确认 |

### 深睡行为
1. 非 bench + 启用深睡 → 开机初始化完就睡；每次录音/上传结束再睡；
2. 睡眠前会等 GPIO15 回到「安静」电平（最多 30s），否则可能一睡就醒；
3. 唤醒后 `复位原因` 日志显示 `深睡唤醒: EXT1 (LM393)`，然后走 VAD 确认 → 录音。

### ⭐ 深睡后怎么再进网页改配置

深睡时 WiFi 和 httpd 都是关的，**网页必然打不开**。固件给了两个入口：

| 入口 | 操作 | 窗口时长 |
|---|---|---|
| **上电/复位配置窗口** | 拔插 USB、按 RST、或网页点「重启」——只要不是被 LM393 唤醒，启动后都会自动开网页 | **120 秒** |
| **三连复位** | 15 秒内连续复位 3 次（按 3 次 RST，或拔插 3 次） | **300 秒** |

窗口内页面顶部会出现橙色徽标 `⚙ 配置窗口: 87s 后进深睡`，倒计时结束设备自动关网页 → 进深睡。
窗口内如果勾上 **Bench 模式**并保存（或关掉「启用深睡」），设备就不会再睡了。

> 注意：窗口只在「非 bench + 启用深睡」时出现；bench 模式下网页本来就常驻。
> 另：如果 WiFi 密码本身是错的，任何窗口都进不去（固件没有 AP 配网兜底）。

## 9. 按钮与底层接口对照

| 按钮 | 调用的接口 | 说明 |
|---|---|---|
| ▶ 开始录音 | `POST /api/record/start` | 手动触发（不等 VAD，直接录） |
| ■ 停止 | `POST /api/record/stop` | 立即停并关文件（会回填头、写元数据） |
| ⬆ 立即上传 | `POST /api/upload` | 上传所有待传文件 |
| ❤ 服务器检查 | `GET /api/health` | 请求后端 `/health`，结果显示在提示条 |
| 扫描 WiFi | `GET /api/wifi/scan` | 下拉框列出 SSID + RSSI |
| 💾 保存配置 | `POST /api/config` | 写 NVS，立即生效（WiFi 类需重启） |
| ↻ 重新读取 | `GET /api/config` | 用设备当前值覆盖表单 |
| 格式化 SD | `POST /api/format` `{"confirm":"YES"}` | 会清空卡，二次确认 |
| 重启 | `POST /api/reboot` | 软重启，约 3 秒后恢复 |
| 刷新列表 / 刷新日志 | `GET /api/files` / `GET /api/log` | 不自动刷新 |

工具链/排障用的额外接口（网页上没有按钮）：

| 接口 | 用途 |
|---|---|
| `GET /api/sdtest?start=<块>&count=<n>[&nsec=<k>]` | 原始块读取自检，返回失败块号（找坏块专用） |
| `POST /api/sd/recover` | 卸载→重新初始化→挂载（卡 CRC 锁死后恢复，不必断电） |

## 10. 录音文件表

- 列出 SD 上全部 `.wav`：文件名 / 大小 / 状态（已上传=有 `.up`，待上传=没有）；
- 文件名可点击 **直接下载**（走 `GET /api/file?name=...`），用于听感验收或 ffprobe 分析；
- 下载不改变「待上传」状态。

---

## 11. 日志面板

- 显示最近 100 条设备日志（含 `ESP_LOG` 与关键业务日志），5 秒自动刷新；
- 排障先看这里：`录音结束 / 上传成功 / SD 写坏 / VAD 未确认 / 进入深睡` 都在其中；
- 完整日志还是要接串口（`idf.py monitor`），网页缓冲会被冲掉。

## 12. 典型使用流程

### 12.1 第一次上电
1. 串口看启动日志：`PSRAM 8MB` → `SD 挂载成功` → `WiFi 已连接` → `NTP 对时成功` → `配置网页已启动`；
2. 浏览器打开设备 IP，确认顶部「状态 idle / WiFi 已连接 / 时间 NTP 已同步」；
3. 点「服务器检查」，应显示 `健康检查 OK`；
4. 点「开始录音」，观察电平条是否随说话跳动；
5. 停止后点「刷新列表」，点文件名下载试听。

### 12.2 录音链路测试（不接传感器）
```
分段=15s，最长=15s，静音停录=0，增益=3
→ 开始录音 → 等 15s → 自动停 → 列表出现 part1（约 481KB）
→ 下载试听 / ffprobe 确认 16000Hz mono s16
```

### 12.3 说话自动停录测试
```
分段=45s，最长=45s，静音停录=2500ms，VAD阈值=6
→ 开始录音 → 说话 8s → 停口 → 约 2.5s 后自动停（文件≈13s）
```

### 12.4 上传/补传测试
```
停掉后端 → 录 15s → 列表显示「待上传」，待上传数 +1
→ 启动后端 → 点「立即上传」→ 状态变「已上传」，后端 /api/uploads 出现记录
```

### 12.5 换卡后恢复
```
插入新卡 → 设 sd_freq_khz=20000 → 点「格式化 SD」→ 刷新列表应为空
→ 录一段验证 → 下载确认可播放
```

### 12.6 调增益（麦克风偏小/爆音）
1. 点「开始录音」，观察电平条；
2. 正常说话应在 **-30 ~ -20 dBFS**，太低就 +1 档增益，接近 0 且声音发闷就 -1 档；
3. 保存后必须重新录一段下载试听（网页只显示实时值，不代表最终音质）。

## 13. 注意事项与常见误用

1. **bench 模式不关 WiFi**：正式功耗策略要关掉 bench；关掉后网页只在启动窗口可访问。
2. **录音中不要频繁点「刷新列表」**：读目录会与写卡抢 SD 总线（固件有锁，但劣质卡更容易崩）。
3. **改 WiFi 后要重启**才重连。
4. **`silence_stop_ms=0` 不会自动停**，记得点「停止」或靠最长时长兜底。
5. **格式化会清空卡**，且 1MHz 下 32GB 卡格式化要 3 分钟以上（先设 20000 再格式化）。
6. **`vad_enable` 当前是预留开关**，没有实际效果（VAD 始终启用）。
7. **配置存在 NVS**：升级固件时若 `CFG_VERSION` 变了，参数会恢复默认（WiFi 也要重填）。
8. **网页没有鉴权**：同一局域网内任何人都能打开并改配置，正式部署建议加反向代理/白名单。

## 14. 接口速查（供脚本/后端联调）

```bash
BASE=http://192.168.5.32

curl -s $BASE/api/status
curl -s $BASE/api/config
curl -s -X POST $BASE/api/config -H 'Content-Type: application/json' -d '{"gain_shift":3}'
curl -s -X POST $BASE/api/record/start
curl -s -X POST $BASE/api/record/stop
curl -s -X POST $BASE/api/upload
curl -s $BASE/api/files
curl -s -o out.wav "$BASE/api/file?name=mic1_2026-10-29_01-18-53_part1.wav"
curl -s $BASE/api/log
curl -s $BASE/api/health
curl -s $BASE/api/wifi/scan
curl -s -X POST $BASE/api/format -H 'Content-Type: application/json' -d '{"confirm":"YES"}'
curl -s -X POST $BASE/api/sd/recover
curl -s "$BASE/api/sdtest?start=29890&count=16"
curl -s -X POST $BASE/api/reboot
```

> 设备 → 后端的接口契约是另一份文档：[`backend-api.md`](backend-api.md)；
> 网页只负责改配置和手动触发，不参与上传格式。
