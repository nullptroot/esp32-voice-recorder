## 2. 断网重启后时间丢失（已修）

### 2.1 现象与根因

- 设备没有电池 RTC；**断电/复位后系统时间回到 1970**。
- 旧固件只在开机连上 WiFi 后做一次 NTP；若当时断网/路由器没起来，NTP 失败。
- 录音时 `time_sync_trusted()` 为 false → 文件名回退成 `mic1_session-01xx_part1.wav`，完全没有时间。
- 本轮实测设备上确实积了 `session-0087` ~ `session-0157` 的大量无时间文件（现已上传到后端）。

### 2.2 修复

1. NTP 成功、深睡前、每 10 分钟，把当前 epoch 写入 NVS（键 `last_epoch`，值不变不重复写）。
2. 开机 `time_sync_init()`：若系统时间 < 2024-01-01，读 NVS 并 `settimeofday()` 恢复；
   标记 `time_source = "restored"`（误差 = 断电时长，属于近似时间）。
3. 录音文件名改用 `time_sync_valid()`：**近似时间也带日期**；
   JSON 里 `time_trusted=false` + `time_source="restored"`。
4. 联网后自动 NTP 校正；未校准时主循环每 60 秒重试一次。
5. 网页时间徽标显示 `NTP 已同步 / RTC 保持 / 近似(断电恢复) / 不可信`。

### 2.3 验证证据

开机日志（冷启动，系统时间归零后从 NVS 恢复）：

```

...
W (5524) time: NTP 对时成功: 2026-10-31 22:22:49 (TZ=CST-8)
```

修复后录制的测试文件（网页手动触发 5.8s）：

```

I (33265) upload: 上传成功: mic1_2026-10-31_22-23-08_part1.wav -> HTTP 200 (stored)
```

后端记录：

```

```

深睡唤醒后的录音（RTC 时间保持）同样带时间：


网页状态：`time_trusted=true, time_source="ntp", time_now="2026-10-31T22:46:37+08:00"`。

### 2.4 局限

- 近似时间的误差 = 断电时长；如果断电几天，文件名日期会差几天，联网 NTP 后新文件恢复正常。
- `time_trusted=false` 时后端仍以 `received_at` 为准（符合 `backend-api.md` §5）。
- 时间恢复只解决"文件名有日期"，不能凭空恢复断电期间的准确时刻。

## 3. 三连 RST → GPIO14 配置/唤醒键（已换方案）

### 3.1 原方案的问题

- 旧固件只有 **WiFi 连上之后**才开配置窗口；断网时第三次复位也会直接进深睡，
  表现就是"复位了、板子重启了，但 WiFi 又关了"。
- 三连复位用 NVS 计数 + 15 秒窗口，节奏稍慢就清掉，实测不可靠。
- 用户明确要求"不要这些按键了，换一个新引脚搞个按钮"。

### 3.2 新方案

- **移除三连 RST 逻辑**（`RST_STREAK_*` 全部删除）。
- 新增 **GPIO14 配置/唤醒键**（RTC GPIO，内部上拉，按下接 GND）：
  - 深睡时按下 → EXT1 唤醒 → 直接开 **300 秒配置窗口**，**不录音**；
  - 醒着短按 → 打开/延长配置窗口 300 秒；
  - 醒着长按 ≥2s → 补传；
  - 唤醒后 2.5 秒内忽略本次按压，避免"按住唤醒"被误判成长按。
- 配置窗口逻辑重写：
  1. **先开窗口，再连 WiFi**；WiFi 连不上也保持唤醒；
  2. 窗口内每 10 秒重试 WiFi（断网改配置的场景）；
  3. 网页保存配置后自动把窗口延长到 300 秒；
  4. 窗口结束才进深睡；
  5. 上电/复位仍有 120 秒窗口（GPIO14 之外的兜底）。
- 网页新增「💤 立即深睡」/ `POST /api/sleep`，方便测试/省电。
- 修掉一个隐藏 bug：URI handler 默认 16 个，新增第 17 个 `/api/sleep` 时被静默丢弃
  （日志 `httpd_register_uri_handler: no slots left`），已把上限改为 24。

### 3.3 验证证据

深睡后点 GPIO14，串口日志：

```
I (929) main: 复位原因: 8, 深睡唤醒: EXT1 (mask=0x4000, 声音=0, 配置键=1)
W (1375) main: 配置窗口: 300 秒内可打开 http://<ip>/ 改配置, 之后自动进深睡
I (3155) main: 由配置键唤醒: 本次只开配置窗口, 不录音
```

用户实测：点 GPIO14 后网页可以打开；第一次打不开是因为设备还在启动（约 3 秒），
等几秒再刷新即可。配置保存后日志出现 `配置窗口已延长至 300 秒`。

GPIO14 接线（杜邦线即可验证）：

| 按键 | ESP32-S3 | 说明 |
|---|---|---|
| 一端 | **GPIO14**（上排，RST 右边第一个脚，丝印 `14`） | RTC 域，EXT1 唤醒 |
| 另一端 | **GND** | 按下拉低 |

## 4. BUG-1：深睡板载 LED 常亮（未修好，已停用指示灯）

### 4.1 本轮试过的软件方案（均失败）

用户三次目视确认：深睡时 GPIO48 上的板载 LED 仍然亮；唤醒后才灭。

1. 冻结 LED 任务 + 活动配置输出高 + `gpio_hold_en(48)` + `gpio_deep_sleep_hold_en()`
   + 关闭 `SLP_SEL` + 睡眠上拉 → **仍亮**；
2. `SLP_SEL` + 睡眠输出高 + 睡眠上拉 → **仍亮**（甚至可能被输出寄存器掉电拉低）；
3. `SLP_SEL` + 睡眠方向=输入 + 睡眠上拉 → **仍亮**。

### 4.2 结论

- GPIO48 不是 RTC GPIO；深睡时数字域掉电，引脚既不能被 hold 驱动，也拿不到常电域上拉。
- LED 阳极接 3.3V、阴极经限流电阻接 GPIO48；引脚悬空时漏电流足以点亮 LED。
- 软件无法完全关断；**10kΩ 上拉（GPIO48 ↔ 3V3）是唯一稳妥的硬件修法**。
  加上拉后：深睡高电平 → 灭；录音时 GPIO48 拉低（强驱动）→ 亮，10k 只多耗 0.33mA。
- 零成本替代（仅限不再用板载 LED）：当前固件已停用板载 LED、永不拉低 GPIO48，
  可直接用杜邦线把 GPIO48 ↔ 3V3 短接，深睡/醒着都灭；以后恢复 LED 前必须拆线并改 10k。
- 用户决定：**不搞这个灯了，板载 LED 停用**。

### 4.3 当前固件行为

- `led_task` 不再写 GPIO48；初始化时拉高，醒着时保持**灭**。
- 深睡时仍可能亮（硬件漏电），**不代表在录音**。
- 录音指示改用外接 GPIO47（慢闪/快闪/双闪/常亮），但**当前未接线**，
  所以设备目前没有可用的录音指示灯。

## 5. GPIO41 按键实测（P1-1，已通过）

方法：杜邦线一头接 GND，另一头点 GPIO41（下排，丝印 `41`）。

串口日志（`logs/serial-r3.log`）摘录：

```
I (187471) led: 按键 GPIO41 长按 (>=2s)
I (260514) led: 按键 GPIO41 短按 (940ms)
I (260971) rec: 手动触发录音 (触发源=2)
I (263681) led: 按键 GPIO41 短按 (780ms)
I (263880) rec: 录音结束: 1 段 / 2 秒 / 88064 字节
I (265817) upload: 上传结束: 成功 1, 失败 0, 重复 0

I (278283) led: 按键 GPIO41 短按 (200ms)
I (278675) rec: 手动触发录音 (触发源=2)
I (283883) led: 按键 GPIO41 短按 (240ms)
I (284082) rec: 录音结束: 1 段 / 5 秒 / 167936 字节
I (286190) upload: 上传结束: 成功 1, 失败 0, 重复 0

I (292864) led: 按键 GPIO41 长按 (>=2s)
I (350285) led: 按键 GPIO41 长按 (>=2s)
```

结论：

- **短按**：空闲 → 开始录音；录音中 → 停止并自动上传。✅
- **长按 ≥2s**：触发补传（无待传文件时日志为"没有待上传文件"）。✅
- 偶尔出现 40ms 的抖动短按（杜邦线接触弹跳），不影响功能；如需更稳可加 10~100ms 软件消抖。

## 8. 下一步建议

1. **把 LM393 DO 插回 GPIO15**（否则声音唤醒无效）；有条件再加 LM393 5V 供电 + 重标电位器。
2. 可选：GPIO48 ↔ 3V3 加 10k 上拉；如果确定不再用板载 LED，也可直接杜邦线短接
   （固件已停用 LED、不会拉低，才安全）；不加就接受"深睡灯亮"。
3. 外接 GPIO47 状态灯（220Ω~1kΩ 到 GND），恢复录音指示。
4. 安静环境静置 1 小时，统计 VAD 误触发（P1-3）。
5. 功耗实测（P3-1）：深睡电流、唤醒→上传周期能量、1000mAh 续航。
6. AP 配网兜底（WiFi 密码错时自救）。
7. 后端转写/日记链路（P2-2，协议已冻结）。
