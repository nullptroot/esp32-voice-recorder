## 5. SD 卡硬件问题（重要，需要更换）

### 现象
- 挂载、格式化、写文件多数时候成功；
- 但读文件系统元数据（FAT/根目录）时周期性报 `sdmmc_read_sectors: error 0x108`（CRC 错误）；
- 表现为：`wav: 打开失败`、文件目录项 size=0、删除报 I/O error；
- **断电 5 秒后恢复**，随后几分钟内再次恶化。

### 诊断（`/api/sdtest` 原始块读，绕过文件系统）
```
block 1000  : failed 0/12        ✅
block 20000 : failed 0/12        ✅
block 29890 : failed 11/12       ❌  (~15.3MB)
```
后续复测坏区漂移到 block 7547，说明坏区在**扩大**，不是固定坏块。

### 结论
- 该 32GB TF 卡（卷标 `asdfg`）是**劣质/扩容卡**，真实可用容量远小于标称，且会随写入继续恶化；
- 写入看似成功（数据进卡），但文件系统元数据落进坏区后，新建文件/目录更新失败。

### 已实施的缓解
1. **64KB 簇格式化**：把 FAT + 根目录压到前 ~5MB，绕开 15MB 附近的坏区（格式化时间 14s → 3.4s）；
2. **SD 自动恢复**：打开文件失败时自动卸载→重新初始化→挂载后重试（`/api/sd/recover` 也可手动触发）；
3. **完整性校验**：关闭 WAV 后校验目录项大小，损坏分段自动删除；<100 字节的残留文件上传前删除；
4. **建议**：断电重启可临时恢复卡状态（实测有效）。

### 建议
> **换一张正品 TF 卡**（SanDisk / Samsung / Kingston，16–32GB，Class10/U3，High Endurance 更佳）。
> 更换后无需改代码，把 `sd_freq_khz` 调回 10000–20000 即可获得更高写入/上传速度。

## 8. 2026-10-29 晚复验：SD「坏块」结论被推翻（供电问题）

> 触发：用户查 SD 模块说明书，发现 **模块 VCC 必须接 5V**（板载 3.3V LDO，输入 3.3V 时 LDO 压差不足）。
> 改接 5V 后复测，**同一张 32GB 卡（卷标 `asdfg`）**全部正常，未换卡。

### 8.1 结论

| 验证项 | 结果 | 证据 |
|---|---|---|
| SD 原始扇区读（0–200000 块 = 100MB，含 7547/29890 附近） | ✅ 0 失败 | `tools/sd_sweep.py`，修复前 49/49 段全 0 |
| 格式化（20MHz、64KB 簇） | ✅ 3.6s | `POST /api/format` → `{"ok":true}` |
| 格式化后再扫 100MB | ✅ 0 失败 | 同上 |
| 60 秒录音 | ✅ 1,912,876 字节 = 59.78s | `/api/files`、`wave` 解析 |
| 录音文件上传 | ✅ HTTP 200 stored，前后端 SHA256 一致 | 后端 `/api/uploads` |
| 连续 10 次录音 | ✅ 10/10 全部成功、全部上传 | `tools/rec_test.py` |
| 上传后自动删除（delete_after_upload） | ✅ wav/json/.up 一并清理 | 串口 `sd: 已删除` |
| 深睡 → LM393 唤醒 → 录音 → 停录 → 上传 → 再睡 | ✅ 端到端 22.5s | 见 8.3 时间线 |

**结论：10-28 判定的「TF 卡物理坏块」是误判，真正原因是 SD 模块供电不足。**
`docs/verification-report.md` §5 的诊断（坏块漂移）在 3.3V 供电下确实是真实症状，但根因是电源而非卡。

### 8.2 本轮发现并修复的 3 个固件 bug

| # | 问题 | 现象 | 修复 |
|---|---|---|---|
| 11 | 深睡唤醒后**永远不录音** | `由 LM393 唤醒` 后 3s 内直接 `进入 EXT1 深度睡眠`，队列里的录音触发被丢弃 | `app_main.c`：worker 仅在 `uxQueueMessagesWaiting(s_q)==0` 时才深睡（唤醒时会同时入队「开机补传」+「录音确认」，补传完就睡会吃掉后者） |
| 12 | WAV 头回填**每次误报失败** | 每个文件都打印 `[头部回填失败]`，但文件其实是好的 | `wav_writer.c`：校验时把偏移 4 和 40 当成连续 8 字节读，改为分别读 `riff`/`data` 并校验 `riff == data+36` |
| 13 | 上传成功却记录 `(duplicate)` | 日志 `HTTP 200 (duplicate)`，实际是新文件 | `uploader.c`：响应体永远包含 `"duplicate"` 键，改为判断 `"duplicate":true` |
| 14 | 静音停录在真实房间**永不触发** | 唤醒后一直录到 `max_record_seconds`（30 分钟） | `recorder.c`：只有连续 3 帧（60ms）人声才刷新 `last_speech_us`，滤掉键盘/鼠标/门窗瞬态噪声 |
